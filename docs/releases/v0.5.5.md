# Agentic Harness 0.5.5

## 変更

- 通常の進行を短い`plugins/harness/skills/harness-loop/SKILL.md`に集め、runtime、状態移行、
  変更分類、評価、Planner出力例を同じSkillの`references/`へ分離しました。必要な条件だけ読みます。
- 承認済みの開発を開始確認へ戻さず、意味を変えない訂正と既存検証の限定修理を扱います。
  限定修理は期待結果・基準・証拠要件を変えず同Sprint 1回までで、独立した再評価と上限を維持します。
- microは影響範囲、低リスク、独立検証の可否で判断し、記録を小さくできます。
  再開・再評価は変更と関連依存を確認し、無関係なdirtyを理由に全履歴・全回帰を繰り返しません。
- Claude SessionStartは適用条件と実パスの短い案内を返します。非UI製品はコマンド/API/入出力で検証します。
- 初回Plannerを含む全roleでdispatch前にruntime設定を解決します。model/effortの既定継承、
  明示設定、native dispatch、fallbackとresumeの安全条件は維持しました。
- 初期化のno-overwriteを維持し、明示承認済みguidance保守は固有規則と既存変更を残して必要差分を反映できます。
  これをruntime/model設定やAgent定義の変更許可にはしません。

## 互換性と未適用範囲

公開準備時に両hostのinstalled 0.5.4とsource 0.5.4のplugin全27ファイルの一致を確認しました。
0.5.5はこれを基準にした指示改善です。grillingの固定本文・license、runtime resolver、初期化処理と
設定形式を維持し、古いsourceへの機能後退を避けています。これはモデル性能比較の実測ではありません。

plugin更新は既存repoのguidanceや設定を一括更新しません。初期化CLIの既存guidance `upgrade`は未実装です。
必要なguidance保守は明示承認された対象で差分を確認して行い、旧cacheにないreferencesを先行参照しません。
Windows実機の今回の再測定は行っておらず、Mac上の既存portable検査と区別します。

## 検証と導入

公開前にはpositioning、loop参照・hook、runtime config、JSON manifest、および下流管理回帰を確認します。
独立評価と公開後のtag / SHA確認の結果はGitHub Releaseに記録します。

正式更新のコマンド、既存scope・設定・dirtyの保持、installed version確認は[README](../../README.md#インストール済みpluginの更新)を参照してください。
更新後は新しいセッションで利用します。

短い更新依頼:

> Agentic Harnessを公式marketplaceの0.5.5へ更新してください。利用中hostの正式手順で対象marketplaceとpluginだけを更新し、導入scope、設定と既存変更を保持してください。成功後にinstalled versionが0.5.5であることを確認し、新しいセッションでの利用を案内してください。
