# Harness 0.6.1 候補

Issue #12 → #13 → #14 → #15の修正を、v0.6.0 (`dd05b7e`) に対する一つのpatch候補として準備しています。
この文書はsource PR用の候補説明です。main merge・tag・Release、各hostの更新や実業務repoへの適用は含みません。

## 変更

- 評価前に修正対象と見送りを選別します。必須の未達・実証回帰・具体的な重大欠陥には対処し、見送りだけで不合格や再評価の往復を増やしません。
- stateは「現在地」一欄を置換更新し、進捗や検証の詳細は既存の履歴文書へ残します。長い旧stateは有効な承認・制約・counterと原文を保持して移行します。
- 割込み修理の終了条件と具体的な復帰先を保持し、必要な確認後に承認済みの元の依頼へ戻ります。子roleの完了を全体の完了とは扱いません。
- Claude Code / Codexの入口とtemplatesから、開始/復帰・評価前・再開/引き渡し時に同じ正本を読みます。小変更の直接修正・必要検証による完了を維持します。

## 適用

公開後のplugin更新は[READMEの正式手順](../../README.md#インストール済みpluginの更新)に従い、元のmarketplaceとscopeを維持します。
既存repoの指示はplugin更新だけでは変わりません。[upgradeの移行手順](../../plugins/harness/skills/harness-loop/references/migration.md)で
独自規則・承認・dirtyを保った候補をpreviewしてから、承認済み範囲へ適用します。initのno-overwriteを保守移行と混同しません。
旧global `review-convergence:v1` は対象repoの新規則を実読込し、既存規則との整合を確認するまで残します。
その後、別途承認された保守では非Harness環境にも使える7行のfallbackへ縮められます。個人globalやinstalled cacheを自動変更しません。
